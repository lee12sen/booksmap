# Development Guide

BooksMap의 기능을 수정하거나 추가할 때 참고하는 개발 가이드입니다. 제품 범위는 [PRD](./PRD.md)가 우선하며, 구현 구조는 [Technical Design](./TECHNICAL-DESIGN.md)을 따릅니다.

## 개발 흐름

1. 작업 범위를 이슈와 연결하고 `docs/<scope>` 형식의 브랜치를 만듭니다.
2. [Getting Started](./getting-started.md)의 절차로 의존성과 개발 서버를 준비합니다.
3. 관련 도메인 모델, 서비스, Route Handler, 화면 흐름을 확인합니다.
4. 작은 단위로 변경하고 사용자에게 보이는 성공·로딩·오류 상태를 함께 구현합니다.
5. 아래 검증 명령을 실행합니다.
6. 변경 파일과 검증 결과를 Pull Request에 정리합니다.

## 주요 디렉터리

```text
src/
├─ app/                  # App Router 페이지, 레이아웃, Route Handler
│  └─ api/               # 서버 API 엔드포인트
├─ domain/               # 애플리케이션 내부의 표준 도메인 모델
├─ services/             # 검색 등 애플리케이션 서비스
│  └─ adapters/          # Mock 및 외부 데이터 소스 어댑터
└─ lib/                  # 외부 API 연동과 공통 서버 로직
```

문서는 `docs/`에 저장합니다. 기존 문서를 수정할 때는 [PRD](./PRD.md)의 요구사항과 [Technical Design](./TECHNICAL-DESIGN.md)의 설계를 함께 확인합니다.

## 데이터와 서비스 경계

- 화면은 외부 API의 필드명이나 상태값을 직접 사용하지 않습니다.
- 외부 응답은 `src/domain/`의 내부 모델로 변환한 뒤 화면에 전달합니다.
- Mock 어댑터와 실제 API 어댑터는 같은 서비스 경계를 유지해 교체 가능하게 합니다.
- 도서관 중복 제거 규칙은 데이터 출처가 추가되어도 일관되게 적용합니다.
- 대출 상태가 누락되거나 해석되지 않으면 낙관적으로 추정하지 않고 `상태 확인 필요`로 표시합니다.
- 일부 데이터 출처가 실패해도 성공한 결과는 유지하고, 사용자에게 부분 실패를 알립니다.

## API 변경 시 확인할 사항

`src/app/api/`의 Route Handler를 수정할 때는 다음을 확인합니다.

- 필수 쿼리 파라미터가 없을 때 적절한 4xx 응답을 반환하는가
- 외부 API 실패가 사용자에게 이해 가능한 오류와 복구 방법으로 전달되는가
- 부분 성공 결과와 실패 개수가 함께 보존되는가
- 서버 전용 인증정보가 클라이언트 코드나 응답에 노출되지 않는가
- 응답의 도서관·도서·대출 상태가 내부 모델과 일치하는가

## UI와 접근성

- 검색 결과, 지도 마커, 선택 상태가 서로 같은 도서관을 식별하도록 유지합니다.
- 대출 상태는 색상만으로 구분하지 않고 텍스트도 제공합니다.
- 로딩과 오류 상태에 접근 가능한 이름과 보조기술 알림을 제공합니다.
- 모바일에서는 목록과 지도를 세로로 배치할 수 있어야 하며, 넓은 화면에서는 나란히 표시할 수 있어야 합니다.
- 좌표·거리·이동시간을 계산할 수 없을 때 임의의 기본값을 표시하지 않습니다.

## 환경변수와 외부 연동

비밀값은 `.env.local`에만 저장하고 커밋하지 않습니다. `.env.example`에는 변수 이름만 기록합니다. 공공데이터 API와 카카오맵 연동은 인증, 할당량, CORS, 캐싱, 출처 표기, 사용료를 공식 문서로 확인하기 전까지 확정된 것으로 가정하지 않습니다.

## 검증 명령

현재 `package.json`에 정의된 검증 명령은 다음과 같습니다.

```bash
npm run lint
npm run typecheck
npm run build
```

개발 서버는 다음 명령으로 실행합니다.

```bash
npm run dev
```

테스트 도구를 추가하면 `package.json`, [README](../README.md), 이 문서에 전체 테스트와 단일 테스트 실행 방법을 함께 기록합니다.

문제 해결이 필요하면 [Troubleshooting](./troubleshooting.md)을 확인하세요.

## 2. 제품 개요

부산 내 공공도서관의 도서 정보를 한 곳에서 검색하고, 도서를 보유한 도서관의 대출 가능 여부와 위치를 확인할 수 있는 통합 검색 서비스다. 사용자는 도서관 홈페이지를 여러 곳 방문하지 않고도 원하는 도서가 어느 도서관에 있는지 확인할 수 있으며, 자신의 현재 위치 또는 직접 입력한 출발지를 기준으로 거리와 예상 이동시간까지 비교할 수 있다.

### 2.1 문제 배경

현재 사용자가 원하는 도서를 찾으려면 도서관별 홈페이지나 검색 시스템을 각각 방문해야 한다. 집 근처 도서관에 도서가 없을 경우 다른 도서관을 다시 찾아야 하고, 검색 결과가 주소로만 제공되면 지도·거리·이동시간을 별도로 확인해야 한다. 이 과정은 시간이 오래 걸리고 도서관 간 결과를 비교하기 어렵다.

### 2.2 제품 가치

- 부산 지역 공공도서관을 한 번에 검색할 수 있다.
- 도서의 대출 가능 여부를 검색 결과에서 바로 확인할 수 있다.
- 도서관 위치를 지도에서 비교할 수 있다.
- 현재 위치 또는 출발지 주소를 기준으로 거리와 예상 이동시간을 확인할 수 있다.
- 사용자가 실제로 방문할 도서관을 더 빠르게 결정할 수 있다.

## 3. 목표와 성공 기준

### 3.1 제품 목표

1. 사용자가 도서명 하나만으로 부산 공공도서관 전체를 검색할 수 있게 한다.
2. 검색 결과에서 도서관별 소장 여부와 대출 가능 여부를 명확하게 제공한다.
3. 사용자가 결과를 지도와 이동 정보로 비교해 방문할 도서관을 결정할 수 있게 한다.
4. 실제 공공데이터/API를 사용해 검증 가능한 MVP를 만든다.

### 3.2 MVP 성공 기준

핵심 사용자 흐름인 **도서명 입력 → 통합 검색 → 도서관별 대출 상태 확인 → 지도에서 위치와 이동 정보 확인**이 중단 없이 완료되어야 한다.

정량 지표는 실제 데이터와 API 제약을 확인한 후 확정한다. 초기 검증에서는 다음을 확인한다.

- 부산 공공도서관 데이터가 검색 대상에 포함되는가
- 검색 결과가 도서관별로 중복 없이 표시되는가
- 대출 가능 상태가 원천 데이터와 일치하는가
- 지도에 검색 결과 도서관을 정상적으로 표시할 수 있는가
- 위치 권한 허용 및 주소 직접 입력 두 경로가 모두 동작하는가
- 사용자가 검색 결과에서 방문할 도서관을 판단할 수 있는가

## 4. 대상 사용자

### 4.1 주요 사용자

- 구매 비용을 줄이기 위해 공공도서관에서 도서를 빌리려는 부산 시민
- 집 근처 도서관에 원하는 도서가 없어 다른 도서관을 찾는 사용자
- 여러 도서관의 소장·대출 상태와 접근성을 비교하려는 사용자

### 4.2 대표 사용자 시나리오

> 사용자는 읽고 싶은 도서의 제목을 검색한다. 서비스는 부산 공공도서관별 보유 여부와 대출 가능 여부를 보여준다. 사용자는 현재 위치에서 가까우면서 대출 가능한 도서관을 선택하고, 지도에서 이동 경로와 예상 시간을 확인한다.

## 5. MVP 범위

### 5.1 포함 범위

- 반응형 웹앱 기본 화면
- 도서명 검색
- 부산 공공도서관 통합 검색
- 도서관별 검색 결과 목록
- 도서관명·주소 표시
- 도서 보유 여부 표시
- 대출 가능 여부 표시
- 검색 결과와 도서관 위치의 지도 연동
- 사용자 현재 위치 기반 거리·예상 이동시간
- 도보·대중교통 이동수단 선택
- 위치 권한 거부 시 출발지 주소 직접 입력
- 검색 결과 없음, 데이터 오류, 위치 조회 실패 안내
- 실제 공공데이터/API 연동을 위한 데이터 정규화

### 5.2 MVP 제외 범위

- 회원가입·로그인
- 찜 또는 즐겨찾기
- 검색 기록 저장
- 도서 예약·대출 신청
- 도서관 좌석 정보
- 도서명 외 저자·ISBN·출판사·주제 검색
- 도서관별 상세 홈페이지 기능 통합
- 관리자용 데이터 관리 화면
- 알림·푸시 메시지
- 네이티브 iOS/Android 앱

## 6. 핵심 사용자 플로우

### 6.1 기본 검색 플로우

1. 사용자가 서비스에 접속한다.
2. 검색창에 도서명을 입력한다.
3. 검색 버튼을 누르거나 Enter를 입력한다.
4. 서비스가 부산 공공도서관 데이터를 조회한다.
5. 검색 결과를 도서관별 카드 또는 목록으로 표시한다.
6. 각 결과에 도서관명, 주소, 보유 여부, 대출 가능 여부를 표시한다.
7. 결과를 지도에 마커로 표시한다.
8. 사용자가 위치 권한을 허용하면 현재 위치를 출발지로 사용한다.
9. 위치 권한을 거부하면 출발지 주소를 입력한다.
10. 사용자가 도보 또는 대중교통을 선택한다.
11. 서비스가 결과별 거리와 예상 이동시간을 표시한다.
12. 사용자가 결과를 선택해 지도 및 길찾기 정보를 확인한다.

### 6.2 위치 권한 거부 플로우

1. 사용자가 위치 권한을 거부하거나 브라우저가 위치를 제공하지 못한다.
2. 서비스는 검색 결과를 계속 표시하고, 위치 기능만 제한한다.
3. 사용자에게 출발지 주소 입력을 안내한다.
4. 주소 검색 결과에서 출발지를 선택한다.
5. 선택한 출발지를 기준으로 거리·예상 이동시간을 계산한다.

## 7. 기능 요구사항

### FR-01. 도서명 검색

- 사용자는 검색창에 도서명을 입력할 수 있어야 한다.
- 검색어가 비어 있으면 검색을 실행하지 않고 입력을 요청해야 한다.
- MVP에서는 도서명 검색을 우선 지원한다.
- 검색 중에는 로딩 상태를 표시해야 한다.
- 검색 실패 시 재시도 가능한 오류 메시지를 제공해야 한다.

### FR-02. 통합 도서관 검색

- 서비스는 부산 내 검색 대상 공공도서관 데이터를 통합해 조회해야 한다.
- 동일 도서관이 여러 데이터 출처에서 중복 표시되지 않아야 한다.
- 검색 결과가 없으면 검색 결과 없음 상태를 명확히 표시해야 한다.
- 데이터 출처와 조회 기준 시각을 표시할 수 있는 구조를 고려한다.

### FR-03. 검색 결과 표시

각 결과에는 다음 정보를 표시한다.

- 도서관명
- 도서관 주소
- 도서 보유 여부
- 대출 가능 여부
- 거리
- 선택한 이동수단 기준 예상 이동시간
- 지도에서 결과를 식별할 수 있는 상태

대출 가능 여부는 원천 데이터가 제공하는 상태를 사용하되, 상태값이 불명확하거나 오래된 경우 사용자에게 이를 오해시키지 않는 표현을 사용한다. 예를 들어 `대출 가능`, `대출 중`, `상태 확인 필요` 등으로 구분한다.

### FR-04. 지도 표시

- 검색 결과 도서관을 지도에 마커로 표시해야 한다.
- 목록의 결과와 지도 마커는 서로 식별 가능해야 한다.
- 사용자가 결과 목록 또는 마커를 선택하면 서로 연결된 상세 정보가 강조되어야 한다.
- 주소를 좌표로 변환하지 못한 도서관은 결과 목록에 남기되 지도 표시 실패 상태를 안내한다.
- 지도 API 키 등 비밀값은 클라이언트 소스에 직접 노출하지 않도록 운영 방식을 검토한다.

### FR-05. 출발지 설정

- 브라우저 위치 권한을 요청할 수 있어야 한다.
- 권한 허용 시 현재 위치를 출발지로 사용한다.
- 권한 거부·실패·지원하지 않는 환경에서는 주소 직접 입력을 제공한다.
- 주소 검색 결과를 선택해야 출발지로 확정한다.
- 사용자가 입력한 주소를 기준으로 다시 거리와 예상시간을 계산할 수 있어야 한다.

### FR-06. 거리·예상 이동시간

- 사용자는 도보와 대중교통 중 이동수단을 선택할 수 있어야 한다.
- 출발지가 확정되면 각 검색 결과까지의 거리와 예상 이동시간을 요청한다.
- 길찾기 API가 제공하는 값의 기준 시각과 제약을 고려한다.
- 경로를 계산할 수 없는 결과는 전체 검색 실패로 처리하지 않고 해당 결과에 상태를 표시한다.
- 거리·시간 정보가 없을 때 임의의 기본값을 표시하지 않는다.

### FR-07. 반응형 UI

- 모바일 화면과 데스크톱 화면에서 검색과 결과 확인이 가능해야 한다.
- 작은 화면에서는 검색 결과 목록과 지도를 세로로 배치할 수 있어야 한다.
- 큰 화면에서는 목록과 지도를 함께 비교할 수 있어야 한다.
- 로딩, 빈 결과, 오류, 권한 거부 상태가 시각적으로 구분되어야 한다.

## 8. 화면 요구사항

### 8.1 검색 화면

- 서비스 목적을 짧게 설명하는 헤더
- 도서명 검색 입력창
- 검색 버튼
- 검색 예시 또는 입력 안내
- 위치 사용 목적을 설명하는 출발지 설정 영역

### 8.2 결과 화면

- 입력한 검색어
- 검색 결과 수 또는 상태
- 이동수단 선택
- 출발지 상태와 변경 기능
- 도서관 결과 목록
- 지도 영역
- 로딩·오류·결과 없음 상태

### 8.3 결과 카드

- 도서관명과 대출 상태를 가장 먼저 인지할 수 있어야 한다.
- 주소는 지도에서 확인할 수 있는 정보로 제공한다.
- 거리와 예상시간은 출발지와 이동수단 기준임을 명확히 한다.
- `상세 보기`, `지도에서 보기`, `길찾기` 등 행동의 목적을 혼동하지 않도록 구분한다.

## 9. 데이터 및 외부 API 요구사항

### 9.1 데이터 요구사항

서비스는 최소한 다음 데이터를 다룰 수 있어야 한다.

- 도서관 식별자
- 도서관명
- 도서관 주소
- 도서명
- 도서 보유·소장 상태
- 대출 가능 상태
- 도서관 위도·경도 또는 지오코딩 대상 주소
- 데이터 갱신 시각

### 9.2 데이터 정규화

도서관별 API 또는 공공데이터의 필드명과 상태값이 다를 수 있으므로 서비스 내부의 표준 모델로 변환한다. 도서관명·주소 기반 중복 제거 기준, 대출 상태 매핑 규칙, 누락 데이터 처리 규칙을 구현 전에 확정한다.

### 9.3 API 검토 항목

실제 연동 전에 다음을 확인한다.

- 부산 공공도서관 전체 목록을 제공하는 공식 데이터 출처
- 도서 검색 API 또는 도서관별 검색 엔드포인트
- 대출 가능 상태의 의미와 갱신 주기
- API 인증 방식과 키 관리 방법
- 호출량 제한·일일 quota·캐시 허용 여부
- CORS 지원 여부와 서버 프록시 필요성
- 장애·응답 지연·부분 실패 처리 방식
- 공공데이터 이용 조건과 출처 표기 의무

### 9.4 지도·길찾기 API

카카오맵 API를 우선 검토한다. 지도 표시, 주소 검색·지오코딩, 도보 경로, 대중교통 경로가 각각 별도 상품·권한·호출 제한을 가질 수 있으므로 실제 사용 가능한 API 범위를 확인한 후 기술 설계를 확정한다.

## 10. 오류 및 예외 처리

| 상황 | 사용자에게 제공할 처리 |
|---|---|
| 검색어 미입력 | 도서명을 입력해 달라는 안내 |
| 검색 결과 없음 | 다른 도서명을 입력하거나 검색어를 수정하도록 안내 |
| 도서관 데이터 일부 실패 | 성공한 결과를 우선 표시하고 일부 결과 조회 실패를 안내 |
| 전체 API 실패 | 일시적 오류와 재시도 버튼 제공 |
| 대출 상태 누락 | `상태 확인 필요`로 표시하고 임의로 가능/불가 처리하지 않음 |
| 위치 권한 거부 | 검색 결과는 유지하고 주소 직접 입력 제공 |
| 주소 검색 실패 | 주소 수정 또는 다시 검색하도록 안내 |
| 도서관 좌표 변환 실패 | 목록에는 표시하되 지도·거리 정보 unavailable 상태 표시 |
| 길찾기 실패 | 해당 도서관의 경로 정보만 실패 처리하고 다른 결과는 유지 |
| API 호출 제한 초과 | 사용자에게 일시적 제한을 알리고 재시도 안내 |

오류는 브라우저 콘솔에만 남기지 않고 사용자가 이해할 수 있는 메시지와 복구 방법으로 제공한다.

## 11. 비기능 요구사항

### 11.1 사용성

- 첫 화면에서 검색 목적을 이해할 수 있어야 한다.
- 검색 결과의 대출 상태를 색상만으로 구분하지 않고 텍스트로도 표시한다.
- 지도와 목록의 선택 상태를 동기화한다.
- 위치 권한 요청 전에 위치 사용 목적을 안내한다.

### 11.2 성능

- 검색 요청 중 중복 요청을 방지한다.
- 검색 결과가 표시되기 전까지 진행 상태를 보여준다.
- 외부 API 응답이 늦어도 화면이 멈춘 것처럼 보이지 않아야 한다.
- 지도·길찾기 요청은 필요한 시점에 수행해 초기 로딩 비용을 줄인다.

구체적인 응답시간 목표는 실제 API 응답 특성과 측정 결과를 바탕으로 정한다.

### 11.3 접근성

- 키보드만으로 검색과 주요 결과 선택이 가능해야 한다.
- 입력창과 버튼에 명확한 접근성 이름을 제공한다.
- 오류·로딩 상태를 보조기술이 인지할 수 있어야 한다.
- 색상 외에도 텍스트와 아이콘으로 상태를 전달한다.

### 11.4 보안 및 개인정보

- 사용자의 현재 위치와 직접 입력한 출발지는 서비스 목적에 필요한 범위에서만 사용한다.
- MVP에서는 출발지 위치를 서버나 계정에 저장하지 않는다.
- API 키·서버 인증정보를 저장소에 커밋하지 않는다.
- 외부 API 호출에 필요한 키의 노출 범위와 도메인 제한을 설정한다.
- 제3자 지도·데이터 서비스의 개인정보 및 이용약관을 확인한다.

## 13. 검증 계획

### 13.1 데이터 검증

- 실제 부산 공공도서관 목록과 서비스 대상 목록을 대조한다.
- 알려진 도서명을 사용해 복수 도서관 결과가 나오는지 확인한다.
- 대출 가능·대출 중·상태 미상 케이스를 각각 확인한다.
- 데이터 갱신 시각과 실제 홈페이지 표시의 차이를 확인한다.

### 13.2 기능 검증

- 정상 검색
- 빈 검색어
- 결과 없음
- API 지연·실패
- 위치 권한 허용
- 위치 권한 거부
- 주소 직접 입력
- 지도 마커 선택과 목록 선택 동기화
- 도보·대중교통 전환
- 모바일·데스크톱 화면

### 13.3 사용자 검증 질문

- 사용자가 도서관별 홈페이지를 방문하는 문제를 충분히 해결하는가?
- 대출 가능 여부와 위치 정보가 방문 결정에 충분한가?
- 검색 결과 목록과 지도의 배치가 직관적인가?
- 실제 데이터 최신성에 대한 안내가 이해 가능한가?
- 후순위 기능 중 사용자 가치가 가장 큰 것은 무엇인가?

## 15. 완료 조건

MVP는 다음 조건을 모두 충족하면 1차 완료로 본다.

- 사용자가 도서명을 입력해 검색할 수 있다.
- 부산 공공도서관 검색 결과가 한 화면에서 확인된다.
- 결과별 대출 가능 여부가 표시된다.
- 결과 도서관이 지도에 표시된다.
- 현재 위치 또는 주소 입력을 출발지로 설정할 수 있다.
- 도보·대중교통 기준 거리와 예상시간을 확인할 수 있다.
- 위치 권한 거부와 외부 API 오류가 사용자에게 명확히 안내된다.
- 모바일과 데스크톱에서 핵심 흐름이 모두 사용 가능하다.
- 실제 API와 데이터의 이용 조건을 준수한다.

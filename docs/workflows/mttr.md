# MTTR

## 목적

프로덕션 장애가 발생한 후 서비스가 정상적으로 복구될 때까지 걸린 평균 시간을 측정한다.

## 측정 기준

- 시작: 프로덕션 장애가 발생한 시간
- 종료: 서비스가 정상적으로 복구된 시간
- 계산: 각 장애의 복구 시간 합계 ÷ 장애 건수
- 시간대: 한국 시간(KST, GMT+9)

## 측정 방법

각 장애별로 다음 시간을 기록한다.

```text
복구 시간 = 정상 복구 시간 - 장애 발생 시간
MTTR = 모든 장애의 복구 시간 합계 ÷ 장애 건수
```

## GitHub Issue를 활용한 측정

Health Check가 장애를 감지하면 `Incident: Production health check failed` 제목의 GitHub Issue를 자동으로 만든다.
이슈 본문에는 장애 발생 시간을 기록한다.

서비스가 정상으로 돌아오면 Health Check가 같은 이슈에 복구 시간과 복구 소요 시간을 댓글로 남긴 뒤 이슈를 닫는다.
`Calculate MTTR` 워크플로우는 복구 시간이 기록된 종료 이슈들을 모아 평균을 계산한다.

## 예시

```text
장애 1: 2026-10-01 10:00 ~ 2026-10-01 11:30
복구 시간: 1시간 30분

장애 2: 2026-10-03 14:00 ~ 2026-10-03 15:00
복구 시간: 1시간

MTTR: (1시간 30분 + 1시간) ÷ 2 = 1시간 15분
```

## 확인할 항목

- 프로덕션 장애인지 확인한다.
- 장애 발생 시간을 기록한다.
- 서비스가 정상적으로 복구된 시간을 기록한다.
- 각 장애의 복구 시간을 계산한다.
- 장애 건수로 나누어 평균을 계산한다.
- 모든 시간을 KST로 통일한다.

## 자동 계산

Health Check가 장애 발생 시 GitHub Issue를 만들고, 서비스가 복구되면 복구 시간과 함께 Issue를 닫는다.

```text
Health Check → 장애 Issue 생성 → 서비스 복구 → Issue 종료
```

`Calculate MTTR`을 수동 실행하면 복구 시간이 기록된 종료 장애 Issue들의 평균을 계산한다.
